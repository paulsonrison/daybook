# P10 implementation detail

Expands approved P10 after P09. Covers US-019, US-025, US-032 and the remaining automated notification criterion of US-035. P09 must checkpoint before implementation starts.

1. Reuse the separate tenant worker and P08 notification intents. Add forced-RLS communication settings, resident consent/locale, immutable message/document snapshots, attempts, signed-link records and contact attempts. Preserve existing intent history. Server-side provider configuration must explicitly map each agency to its own credentials/phone/service; owners cannot select another agency's sending identity.
2. Implement English, Malayalam and Hindi invoice/reminder/hold templates with exact money and agency identification. WhatsApp automation uses configured, approved official business templates; direct-chat greetings remain distinct. Validate E.164 numbers and explicit channel consent. Missing provider, template or consent produces an honest blocked state, never a sent result.
3. Add single/batch invoice dispatch and manual reminders. Verify tenant ownership and immutable invoice revision, capture current due/UPI intent at preparation, and deduplicate stable request IDs. Batch progress distinguishes prepared, pending, accepted, delivered, failed, unknown and blocked recipients. No real recipient messages during development.
4. Schedule one current-agency-date overdue evaluation at local midnight using configured opt-in frequency/cooldown. Check current positive overdue balances, active contact consent and existing pending/unknown/accepted attempts. Catch-up must not blast one reminder for every missed day. Cooldown and deduplication are enforced transactionally across workers.
5. Claim outbox items with bounded leases and attempt fencing. Persist the point at which provider submission begins before making the external call outside the database transaction. Expired pre-submission claims can retry; uncertain submissions become UNKNOWN and cannot be blindly resent. Acknowledged recipients in a partial batch are never resubmitted.
6. Use official WhatsApp Cloud and SMS provider APIs through typed server transports. Production destinations are fixed official HTTPS endpoints, with test transports injected only by local tests. Keep tokens out of stored payloads, logs and browser responses. A provider acceptance ID is not delivery confirmation. Explicit rejection, timeout and acceptance have different outcomes.
7. Authenticate provider callbacks using the exact raw-body signature and configured account identity. Resolve agency ownership from server configuration; never trust a caller-supplied tenant. Process duplicate/out-of-order callbacks idempotently and monotonically. An uncertain submission can be reconciled through its correlation value or explicit audited owner decision; do not invent a delivery outcome.
8. Generate actual invoice/receipt/payslip PDFs from immutable business snapshots. Prefer the already tested Chrome print engine via Playwright, self-contained escaped HTML and embedded local fonts, including Indic coverage. Block network/service workers in the document context, bound pages/bytes/concurrency/time, and render outside financial transactions. A missing supported browser is a visible generation failure. Reuse shared tokens and source presentation rather than create another theme.
9. Provide owner-authenticated document downloads and narrowly scoped, expiring, revocable bearer links for residents without an agent session. Store token hashes, grant only the selected immutable document and tenant, use no-store responses and safe filenames, and reject unknown/revoked/expired tokens. Defaults: seven-day links; disclose this in the dispatch preview. Tokens must not appear in operational logs.
10. Keep QR codes as payment intents, reuse the verified P08 UPI builder, and show no configured QR when no verified payee identity exists. PDFs/message snapshots identify the issued revision and preparation date; they do not promise a historical due figure remains live after subsequent payments.
11. Add click-to-call and direct WhatsApp greetings to resident profiles, delivery and collection run-sheets. Record the explicit click attempt with agency/resident/channel/time and stable operation ID; opening a link is an attempt, never proof a call or message arrived. Do not block the actual user click behind a browser-popup-disallowed asynchronous redirect.
12. Build settings/consent, dispatch/history, reminder controls and document status from shared UI, with missing/loading/error/stale/partial/unknown states and original-request recovery. Preserve P08 service-hold status honesty and activate its real dispatch intent only when configured and consented. Keep complete histories separate from an apparent live provider status.
13. Observe RED to GREEN for consent/tenant/phone/template guards, actual PDFs and Indic fonts, link expiry/revocation, exact provider contracts, callback signatures/replay/order, uncertain-send handling, partial batch recovery, cooldown races, overdue-only midnight evaluation and direct-contact attempt logging. Use synthetic recipients and loopback transports. Run the project suites, independent reviews, fixes and rereviews before checkpointing.

Ruling: a timed-out provider submission has an unknown outcome. A stable internal operation ID alone does not prove the external provider deduplicates requests. Prefer reconciliation over an automatic resend that could contact a resident twice.

Ruling: the current Meta message API does not document `biz_opaque_callback_data` for message sends. Do not use call-only metadata as a message correlation guarantee. WhatsApp callbacks correlate through returned provider IDs; an unknown send without an ID needs verified reconciliation. A Twilio callback can include the internal intent in its configured, signed callback URL.

Ruling: callbacks may arrive before the send response. Retain authenticated normalized events in a tenant-scoped inbox and serialize inbox insertion/application with provider-ID association using the same agency lock, acquired before row locks. A sequential early-callback test alone does not prove the concurrent case.

Ruling: document links are limited bearer capabilities for one immutable document, because residents do not have agent sessions. Owner listing and management remain authenticated and tenant scoped. Expiry and revocation are explicit; no public document directory exists.

It confirms print-media PDF output, background/color controls, service-worker blocking and context request interception. Verify the installed version and runtime during implementation; this planning retrieval is not a completed PDF test.

Interfaces: P08 payment receipt balances and notification intents; P07 immutable invoice revisions/ledger; P09 payslip snapshots and payout state; P05 worker leases and tenant enumeration. P11 will reuse the same dictionaries, Indic fonts, PDF boundary and exact financial sources for reporting. Live provider acceptance remains distinct from local contract verification.
